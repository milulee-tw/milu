Combo Gaming · Feature Brief · 2026

Turning a new player's
first 300 spins from luck into design

We cannot control whether a new player gets lucky — but we can control which set of outcomes they receive.
For each game we pre-build two pools of quality-verified 300-spin sequences and serve them according to the player's current bet size. After 300 recorded bets the game returns to standard RNG. The player sees nothing different at any point.

01 · The problem

96.7% is a long-run average, not anyone's actual experience

Two players can open the same game, with identical maths, and have completely opposite first sessions. One hits a Free Game early and keeps playing. The other runs dry and never comes back for day two. Neither outcome is a design fault — it is simply what probability does over a few hundred spins. Today we have no way to influence it.
Figure 1 · Two new players, same game, first few hundred spins
Both curves have exactly the same expected value. The only difference is the order in which results arrive. Player B never sees the game's core feature, and never returns.
02 · The solution

Two script pools, split by bet size

A large simulation is run on our game server for each game, and the output is cut into continuous 300-spin segments. Every segment must pass five quality gates before it enters a pool. There are two pools — a low-stake pool and a high-stake pool — with 100 scripts each. Each spin draws from whichever pool matches the player's bet at that moment. Once the player reaches 300 recorded bets, the mechanism ends.
Figure 2 · Two pools and how the 300-spin window is consumed
Scripts are assigned at random, on first use. The first time a player bets in a band, the server draws one of that pool's 100 scripts at random — no ordering, no counter, nothing an outside observer could predict. When scripts are later compared, only those with enough players behind them are read; thin samples are not used to draw conclusions.
A Free Game counts as one spin. The triggering spin and all of its free spins consume one step of the script and count as one recorded bet; the big-win limit is checked once for the whole round.
Why 300 and not longer
Current data shows most players' session volume sits around 300 spins — the same length as one script. Extending the window does not hold people longer; it only makes the cost of the favourable period harder to control.
The 300-bet cap is hard: not per pool, no replay, no extension. However a player moves between bet bands, the window does not get longer.
Players who cross the bet threshold mid-window receive two partial sequences rather than one complete script, so the five gates are not guaranteed for them. This is an accepted trade-off: what is lost is the guarantee, not the experience — the scripts are ordinary sequences drawn from simulation, so a partial run behaves much like standard RNG rather than worse. We monitor how often this happens and will revisit the rule if it turns out to be common.
Two scope limits at launch. The mechanism only engages when both conditions hold: the game is Lucky Paws, and the player's wallet currency is THB. Players on any other currency are passed straight to standard RNG — no script is assigned.
Thresholds for 62 currencies are already defined (benchmarked to THB 50, held as fixed values rather than live FX so a player cannot drift between pools as rates move). Extending to further currencies is a configuration change — no change to the mechanism or the scripts themselves.
Bought Free Games are excluded. When a player purchases a Free Game (buy bonus), that spin uses standard RNG and consumes no script progress. The scripted sequence stays intact rather than having spins carved out of it, which would break the quality guarantees.
03 · Quality standard

Every script passes five gates

All five must pass. If a 300-spin segment fails any one of them it is discarded and the next segment is evaluated. The two pools differ only in their RTP band — the other four gates are identical.
Gate 1 · RTP · Low-stake pool
100–105%
bet < THB 50. A slightly positive first experience — the game feels fair and rewarding.
Gate 1 · RTP · High-stake pool
98–100%
bet ≥ THB 50. Expected value is negative for the player — see section 05.
Gate 2 · Hit rate
> 35%
Governs feel. Prevents wins from clustering into a few spins with long dry stretches between.
Gate 3 · Free Game
≥ 1
At least once per 300-spin script — and the window is the same 300 spins, so a player who stays in one band always sees one. Without it, they have not experienced the game.
Gate 4 · Big Win
≥ 3
A Big Win is a spin paying 10× bet or more; a Free Game round counts as one spin, judged on its total. Frequent small wins alone do not feel rewarding.
Gate 5 · Max single win (a Free Game round counts as one spin)
< 500×
No outsized win during the new-player window — cost stays predictable and the later drop-off is less jarring.
Gate 5 is measured per spin, where a Free Game round counts as one spin judged on its total payout. This naturally covers sequences where each free spin is modest but the round's total is not.
04 · Order of precedence

The prize cap always comes first

This mechanism never overrides existing risk controls. Whenever a scripted result would exceed the line's available prize pool, the prize cap wins and the script gives way for that spin.
Figure 3 · How each spin is resolved
How the prize pool works: each line holds its own pool, seeded at launch. Player losses flow into it and player wins are paid out of it. When a spin's net win would exceed the remaining balance, that win is capped to a low win — a value close enough to zero to be treated as zero — so the pool can never go negative. In practice this is rare: the scripts contain no win at or above 500× bet, so the cap is very unlikely to trigger at normal bet sizes.

The feature itself is configured per line and disabled by default; enabling it on a given line is a written request handled on our side, with no self-service switch in any back office.
05 · Protection by design

Farming the scripts is a losing proposition

A mechanism that gives new accounts a favourable experience invites an obvious question: what stops someone from opening accounts repeatedly to harvest it? The answer is built into the pool structure rather than bolted on afterwards.
Figure 4 · Maximum a single new account can extract (THB · expected value · 300 spins)
Low-stake pool: 300 × THB 49 × 2.5% ≈ 368, and only if every single spin sits right at the threshold.
High-stake pool: 300 × THB 200 × −1% ≈ −600 — an RTP of 99% means the player's expected result is a net loss.
Layer 1 · Structural
High-stake pool is EV-negative
To harvest at scale you must bet large — and betting large puts you in the 98–100% pool. The incentive disappears at the source.
Layer 2 · Structural
THB 50 is the pool boundary
Not a bet cap — any bet of THB 50 or more simply lands in the negative-expectation pool. Below it, the expected take across 300 spins is roughly THB 368, and even at the 105% RTP ceiling no more than about THB 735.
Layer 3 · At source
No win reaches 500×
Scripts contain no outsized win at all, so no single account can produce a large payout spike.
Layer 4 · System
Prize cap
Existing control, always ahead of the script in precedence (section 04).
Layer 5 · Post-launch
Behavioural monitoring
Primarily watching for accounts clustering their bets just under the threshold to stay in the favourable pool.

What ships now, and what comes later

07 · What we measure, and what you get back

Success is measured in spins, not retention

The target for this feature is a higher average number of spins per new player — getting people to play more rounds of the game. It is deliberately not retention.
Why not retention
Retention is the output of the entire new-player funnel — acquisition source, deposit flow, promotions, market conditions, competition from other titles. A single in-game mechanism does not control most of those inputs, and the link between spin volume and retention has not yet been established with data.
Measuring this feature on retention would mean grading it on something neither of us controls. Spin volume attributes cleanly to the mechanism, so that is what we hold ourselves to. Day-1 and day-3 retention are still recorded and still baselined — as observed metrics, and so the spin-volume-to-retention link can be tested later.
Primary
Avg. spins per new player
Total spins ÷ new players in that game. Reported as mean and median together.
Secondary
300-spin completion rate
Share of new players who complete the full window. Most robust measure — both numerator and denominator sit in our own data.
Secondary
First-day spins
Reflects the immediate session, though it varies with how much time a player happens to have.
Observed
D1 / D3 retention
Recorded and baselined, but not used to judge the feature.
Why the median matters as much as the mean. Averages are easily inflated by a small number of heavy players. If the mean improves but the median does not, the mechanism is only working on players who were already going to play a lot — not the ones it was built for. We report both.
07-B · Continuous optimisation

100 scripts per pool means we can tell the good ones from the bad

Because the window is a fixed 300-spin script and every spin is logged, we can see exactly how each script performs — and, more usefully, which of its characteristics made it perform that way. Pattern testing across all 100 scripts in a pool tells us where a Free Game should land, how Big Wins should be spaced, and which scripts to retire.
Figure 5 · Pattern testing across scripts (illustrative)
Both scripts pass all five gates and sit in the same RTP band, so on paper they are equivalent. In play they are not — and the logs show precisely why. Scripts that underperform are retired and replaced; the characteristics that made the strong ones work are carried into the next generation.
Comparisons are only drawn where a script has accumulated enough players to make them valid rather than anecdotal; scripts with thin samples wait until they have.
01
Does it work at all?
Average spins per new player (mean and median) against a 30-day baseline frozen before launch.
02
Which sequences work best?
Spins and completion rate compared across the scripts in each pool — only scripts with enough players behind them are compared, so the result is valid rather than anecdotal.
03
Which characteristics drive it?
Where the first Free Game lands, how Big Wins are spaced, what hit rate actually matters — the inputs to the next generation of scripts.
This does not stop at launch. Pattern testing runs continuously: weak scripts are retired, stronger ones replace them, and what we learn about Free Game placement feeds into the maths design of every future title. The findings are shared with you — the same insight applies to any title in your lobby, not only ours.
