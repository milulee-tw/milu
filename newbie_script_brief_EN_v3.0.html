Combo Gaming · Feature Brief · 2026

Turning a new player's
first 150 spins from luck into design

We cannot control whether a new player gets lucky — but we can remove the two extremes from the run they receive.
For each game we pre-build two pools of verified 150-spin result sets, 2,000 in total, and serve them according to the player's current bet size. After 150 recorded bets the game returns to standard RNG.
The order in which those results appear is random — two players drawing the same set still have completely different journeys.
No additional money is given away — the average RTP of the scripts is the same as standard RNG. What changes is the spread of outcomes, not the average. The player sees nothing different at any point.

01 · The problem

96.7% is a long-run average, not anyone's actual experience

Two players can open the same game, with identical maths, and have completely opposite first sessions. One hits a Free Game early and keeps playing. The other runs dry and never comes back for day two. Neither outcome is a design fault — it is simply what probability does over the first hundred spins or so. Today we have no way to influence it.
Figure 1 · Two new players, same game, the first 150 spins
Both curves have exactly the same expected value. The only difference is the order in which results arrive. Player B never sees the game's core feature, and never returns.
02 · The solution

Two script pools, split by bet size

A large simulation is run on our game server for each game — a million spins or more — and the output is cut into continuous 150-spin segments. Every segment must pass a single gate before it enters a pool: the RTP of the whole 150-spin segment must fall between 85% and 115%.
Bets are routed into three bands — a low-stake pool (THB < 10) and a high-stake pool (THB 10–199), with 1,000 scripts each; bets of THB 200 or more are not scripted at all. Once the player reaches 150 recorded bets, the mechanism ends.
Figure 2 · Three bet bands and how the 150-spin window is consumed
The key change in this version: the RTP is no longer raised.
Both pools now average the natural RTP of the game (≈96.7%, the same as standard RNG). The single gate only removes the two extremes of a 150-spin run — nothing scrapes the bottom, nothing runs away at the top.
In plain terms: a new player does not get better odds, they get a less extreme 150 spins. No additional money is paid out; only the spread of outcomes changes.
The second key change: a script is a set of results, not a sequence.
The 150 entries in a script file are numbered, but that is a data index, not the order the player will see them in. On every spin the server draws one of the results not yet used from that script, at random; once used it never reappears.
Two players drawing the same script therefore have completely different journeys — different points at which the Free Game arrives, different placement of dry stretches.
Nothing about the totals changes: RTP, Free Game count, Big Win count and the maximum single multiplier are all sums over the 150 results, so the 85–115% gate and the 172.5× ceiling hold exactly as before.
What this mechanism does not guarantee. The gate looks at the RTP of the whole 150-spin set, not at what happens inside it — and the order is drawn per player. It therefore does not guarantee that a player will avoid a long dry stretch; how long a dry stretch runs differs for every player and cannot be controlled at the script level at all. It can only be observed after the fact, from the spin logs.
Scripts are assigned at random, on first use. The first time a player bets in a band, the server draws one of that pool's 1,000 scripts at random. Which script is drawn only determines which 150 results the player will meet — the order is decided spin by spin, at random.
A Free Game counts as one spin. The triggering spin and all of its free spins consume one step of the script and count as one recorded bet; the big-win limit is checked once for the whole round.
Why 150 and not longer
The median number of spins played by a departing new player is 66 — half of them never reach 150, let alone 300. A longer window means most of the script is never seen, while the full exposure is still carried.
A 150-spin window covers the range players actually reach, and halves the length of script a single account can consume.
The 150-bet cap is hard: not per pool, no replay, no extension. However a player moves between bet bands, the window does not get longer.
Both pools use the same gate — deliberately. A player who crosses the high-stake threshold moves to an entirely different script, so a small-bet run cannot be used to map a sequence and then replayed at a higher stake. The 2,000 scripts of a game also share no spin with one another.
Players who cross the bet threshold mid-window receive two partial sets rather than one complete script, so the 85–115% band is not guaranteed for them. This is an accepted trade-off: what is lost is the guarantee, not the experience — the scripts are ordinary results drawn from simulation, so a partial run behaves much like standard RNG rather than worse. Both pools use the same gate, so there is nothing to gain by switching. We monitor how often this happens and will revisit the rule if it turns out to be common.
Two scope limits at launch. The mechanism only engages when both conditions hold: the game is Lucky Paws, and the player's wallet currency is THB. Players on any other currency are passed straight to standard RNG — no script is assigned.
Both thresholds for 62 currencies are already defined as fixed amounts in the platform's currency settings — a high-stake threshold and a no-script threshold — held as fixed values rather than live FX, so a player cannot drift between bands as rates move. Extending to further currencies is a configuration change — no change to the mechanism or the scripts themselves.
Two kinds of spin are excluded. A purchased Free Game (buy bonus), and any bet at THB 200 or more (the no-script threshold). Both use standard RNG and consume no script progress. The script's remaining results stay intact rather than having some carved out of it; a player who returns below the threshold simply continues where they left off.
03 · Quality standard

Five gates, reduced to one

A 150-spin segment now has to satisfy a single condition: the RTP of the whole segment must fall between 85% and 115%. Segments that fail are discarded and the next one is evaluated. Both pools use the same gate — there is no difference between them.
The only gate · RTP of the full 150-spin segment
85 – 115%
Removes the two extremes of a run — nothing scrapes the bottom, nothing runs away at the top. Identical for the low-stake and high-stake pools.
Average RTP across both pools
≈ 96.7%
The natural rate, identical to standard RNG. This version does not raise it: no additional money is paid out.
Why the other four gates were removed. Requiring five conditions at once left very few qualifying segments, which concentrated the pools on unusual runs — and the more conditions there are, the harder it is for 2,000 scripts to stay independent of one another, which is what the analysis in section 07-B depends on.
Removed: hit rate > 35%, Free Game ≥ 1, Big Win ≥ 3, max single win < 500×.
Two guarantees end with those gates.
① A 150-spin script is no longer guaranteed to contain a Free Game.
② Hit rate is no longer constrained, so a long dry stretch is not ruled out (see section 02).
Both points are stated here rather than left implicit, because the previous version's wording claimed otherwise.
Outsized wins are still impossible — and the limit is now tighter.
The previous version enforced this with a gate (max single win < 500×). It is now guaranteed by arithmetic instead: a script is 150 spins and its RTP cannot exceed 115%, so the total multiplier of the whole script cannot exceed 172.5× — and therefore no individual spin within it can exceed 172.5× either. Tighter than the old 500× gate, with one fewer check to run.
Fewer conditions, but many more scripts — and no overlap. The requirement rises from 200 to 2,000 scripts per game (1,000 per pool), and no two scripts may share a single spin, across pools as well as within them.
04 · Order of precedence

The prize cap always comes first

This mechanism never overrides existing risk controls. Whenever a scripted result would exceed the line's available prize pool, the prize cap wins and the script gives way for that spin.
Figure 3 · How each spin is resolved
How the prize pool works: each line holds its own pool, seeded at launch. Player losses flow into it and player wins are paid out of it. When a spin's net win would exceed the remaining balance, that win is capped to a low win — a value close enough to zero to be treated as zero — so the pool can never go negative. In practice this is rare: the arithmetic of the gate means no spin inside a script can pay more than 172.5× bet — a ceiling that does not widen with the size of the bet — so the cap is very unlikely to trigger.

The feature itself is configured per line and disabled by default; enabling it on a given line is a written request handled on our side, with no self-service switch in any back office.
05 · Protection by design

There is nothing to farm

A mechanism that gives new accounts a controlled experience invites an obvious question: what stops someone from opening accounts repeatedly to harvest it?
In this version the answer is structural rather than defensive: the scripts average the game's natural RTP, so every one of the three bet bands carries the same negative expectation as ordinary play. There is no positive-expectation band to harvest.
Figure 4 · Expected result for a single new account across the whole window (THB)
All three bands carry the same −3.3% expectation (the game's 96.7% RTP); only the turnover differs.
Illustrative: low-stake 150 × THB 5 × −3.3% ≈ −25; high-stake 150 × THB 100 × −3.3% ≈ −495.
A bet of THB 200 or more bypasses the scripts entirely, so a larger bet cannot be used to amplify what a script pays.
Layer 1 · Structural
Every band is EV-negative
The scripts average the game's natural RTP, so no band offers a positive expectation. Farming the scripts is the same proposition as playing the game normally.
Layer 2 · At source
No spin can exceed 172.5×
Not a gate but arithmetic: 150 spins at an RTP ceiling of 115% gives a total multiplier of 172.5×, so no single spin can exceed it. Tighter than the previous 500× rule.
Also structural
The order is drawn per player, so nothing can be mapped by observation
Even if two accounts draw the same script, the order they see it in is different. Recording and comparing sessions cannot even establish that two accounts share a script, let alone predict the next spin — reconstructing a script's contents would require playing all 150 spins, by which point the window has already closed.
Layer 3 · System
Prize cap
Existing control, always ahead of the script in precedence (section 04).
Layer 4 · Post-launch
Behavioural monitoring
Primarily watching for accounts clustering just below the no-script threshold, where the 85% floor protects the largest amount.

07 · What we measure, and what you get back

Success is measured in spins, not retention

The target for this feature is a higher average number of spins per new player — getting people to play more rounds of the game. It is deliberately not retention.
Why not retention
Retention is the output of the entire new-player funnel — acquisition source, deposit flow, promotions, market conditions, competition from other titles. A single in-game mechanism does not control most of those inputs, and the link between spin volume and retention has not yet been established with data.
Measuring this feature on retention would mean grading it on something neither of us controls. Spin volume attributes cleanly to the mechanism, so that is what we hold ourselves to. Day-1 and day-3 retention are still recorded and still baselined — as observed metrics, and so the spin-volume-to-retention link can be tested later.
Primary
Avg. spins per new player
Total spins ÷ new players in that game. Reported as mean and median together.
Secondary
150-spin completion rate
Share of new players who complete the full window. Most robust measure — both numerator and denominator sit in our own data.
Secondary
First-day spins
Reflects the immediate session, though it varies with how much time a player happens to have.
Observed
D1 / D3 retention
Recorded and baselined, but not used to judge the feature.
Why the median matters as much as the mean. Averages are easily inflated by a small number of heavy players. If the mean improves but the median does not, the mechanism is only working on players who were already going to play a lot — not the ones it was built for. We report both.
07-B · Continuous optimisation

Every player's journey is a data point of its own

Because the window is a fixed 150 spins and every spin is logged, each player's actual journey is a known combination of characteristics — how far in the first Free Game arrived, how Big Wins were spaced, how long the longest dry stretch ran. Since the order is drawn per player, every player who passes through the window is a separate data point on which characteristics drive spin volume — not 2,000 points, but as many as there are players.
Figure 5 · Characteristics analysis across player journeys (illustrative)
Both groups pass the same gate and sit in the same RTP band, so on paper they are equivalent. In play they are not — and the logs show precisely why. Because the order is drawn per player, the comparison is built in: players who met the Free Game early and players who met it late can be read against each other directly, within the same population. What separates them feeds the production conditions of the next generation of scripts (Free Game frequency is something a script controls; where it lands is not).

02
Which characteristics drive it?
How far in the first Free Game arrived, how Big Wins were spaced, what hit rate actually matters, how long the longest dry stretch ran — read per player journey, not per script. The sample is the number of players, not 2,000.
Why this replaces "which script is best". Two reasons. With 1,000 scripts per pool, no individual script accumulates enough players for a per-script comparison to be meaningful — and more fundamentally, a script no longer corresponds to a single experience, since the order is drawn per player. Reading journeys rather than scripts needs no per-script sample size and grows sharper with every player who passes through.
This does not stop at launch. The characteristics analysis runs continuously, and what it shows about Free Game frequency and win spacing feeds into the production conditions for the next generation of scripts and into the maths design of every future title.
The first review is scheduled for week 8 after launch, and the findings are shared with you — the same insight applies to any title in your lobby, not only ours.
