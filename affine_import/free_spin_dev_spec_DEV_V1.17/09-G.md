# 🏗 09-G · 開發前置條件（基礎建設）

> 依據：規格 DEV V1.20（依文件矛盾審查報告修正結算觸發、逐局注單、到期結算時點與歷程顯示；上限欄位統一為 max_bonus；其餘產品規則沿用 DEV V1.15）
> 來源：DEV V1.15 §02–§03、§10–§12；DEV V1.16 共用規則整理
> 職能：🏗 基礎建設 · ⚙ 後端

> 🚫 **基礎建設 · 先做，否則全卡關**：以下五項是地基，任何一項沒先就位，發卡、結算或查詢的鏈路就動不了。

- 🔐 **① 與集成商往來憑證的安全保管 〔基建〕**：與集成商往來所需的憑證／金鑰，須存放在安全位置並由專責模組使用，不得散落在程式碼或設定檔明文中。
**沒先做會卡什麼：**無法與集成商建立可信往來，發卡通知完全送不出去。
- ⏰ **② 過期結算掃描排程（每 15 分鐘） 〔基建〕**：伺服器**每 15 分鐘**掃描一次「已到期、未結算」的卡並觸發整卡結算與狀態轉換，**到期後 15 分鐘內完成入帳**；玩家正在遊戲中時，當下那一局照常結束、下一次下注即判定失效並結算，不等排程〔V1.20 改〕（**次數用完的結算由最後一局結束時即時觸發**，不靠排程）。
**沒先做會卡什麼：**到期卡不會被結算、玩家拿不到錢；過期卡也不會轉唯讀，客訴必然發生。
- 🎫 **③ 一次性遊戲通行證＋防連點 〔基建〕**：進入遊戲的一次性入口產生、失效重取、與同卡節流機制。
**沒先做會卡什麼：**玩家點「進入遊戲」會遇到連結失效死路，多卡綁定也無從保證。
- 🔎 **④ AWC FREE SPIN 狀態查詢 〔基建〕 〔V1.6 新增〕**：需**集成商提供「玩家 × 遊戲」維度的 AWC FS 進行中狀態查詢介面**。**查詢時機＝背包展開卡片載入遊戲牆時 ＋ 進場啟用前再驗一次**（兩道防線）。
**沒先做會卡什麼：**同一款遊戲同時存在 AWC FS 與 COMBO FS 卡時兩者互相干擾，玩家會遇到「卡使用失敗」卻查不出原因，次數與 score 也可能對不起來。
- 🗂️ **⑤ FS 逐局注單過濾 ＋ 歷程 API 統一輸出 〔基建〕 〔V1.12 新增〕**：FS 卡的每一局以「免費轉注單狀態」**寫在注單表**（見 09-A 注單機制），**一般注單檢視與報表須濾掉這個狀態**〔V1.20 改〕；同時**遊戲歷程 API 須調整為「同一份資料輸出」**——一般注單與 FS 歷程**吃同一份來源**，不得兩處各自維護。
**沒先做會卡什麼：**[04 玩家端遊戲歷程](affine://04-A) 的四層畫面**全部沒有資料可撈**，玩家與客服都查不到 FS 的任何一局；兩處各自維護則必然出現「背包顯示的 score 與歷程列出的局加總對不起來」的對帳爭議。
**連動範圍：**此項同時連動 RTP 判斷、對帳與活動數據統計，**不宜與 CRM 功能開發搶同一批後端人力**。

## 遊戲端回傳的錯誤訊息〔V1.18 新增〕

> ℹ️ **這是本文件唯一列出錯誤訊息的地方。**原則上本書不指定錯誤代碼（見 [00-A 功能目的與範圍](affine://00-A) 文件定位），但下列訊息**玩家端必須各自對應處理**——顯示什麼文案、能不能重試、要不要擋下開局——所以在此列出。**訊息字串本身以遊戲端實作為準**，本表只界定「什麼情況會收到它」。

| Message | 觸發時機 |
|---|---|
| `free voucher not found` | 玩家送的 ref 不在 server cache（卡剛過期被 cron 清、非法 ref、client 快取失效） |
| `game not supported by this voucher` | 卡的 `game_code` 不含當前遊戲 |
| `invalid spin parameter for voucher` | 幣別／BuyType／BetAmount 不符卡的規範 |
| `voucher rounds used up` | `spin_count >= round`，局數已用完仍送出 spin（最後一局結束即自動結算、不需玩家領獎；此錯誤只在前端尚未收到結算結果時出現）〔V1.20 改〕 |
| `free voucher expired` | 卡已過 `end_time` |
| （空 message · Before StartTime） | 卡還沒生效（`start_time > now`） |
| `AWC free spin available for this game, please use it first` | 同遊戲有 AWC 卡未用完，禁止使用 CRM 卡 |
| `free voucher not owned by member` | 玩家 A 拿 B 的 ref（多見於 hack／bug） |
| `free voucher settle failed` | 結算失敗（非 PENDING 的失敗）；**同樣寫入 `order_state` = 5、`settle_status` = 4，交由 Retry 機制重試**（見 09-A）〔V1.20 補〕 |

> ⚠️ **玩家端不得直接顯示這些英文原文。**`AWC free spin available for this game, please use it first` 對應的玩家端文案，依 DEV V1.7 定案為「**請先完成此遊戲的免費旋轉**」——**玩家端一律不出現「AWC」字樣**（見 09-I 多國語系總表）。每一條實際要顯示的文字見下方〈**玩家端錯誤文案**〉；其餘語系翻譯見 [09-E 待確認 ⑬](affine://09-E)。

## 非錯誤、但需要辨識的回應狀態〔V1.18 新增〕

下列三種情境的 `code` 都是 **0**（不是錯誤），玩家端要再看 `settle_status` 與 `payout` 才知道實際發生什麼，不可一律當成功處理。

| 情境 | Response |
|---|---|
| 領獎失敗但已 PENDING | `code = 0` ＋ `voucher.settle_status = 4` → SETTLE NOW 反灰、禁止重複點擊，交由 Retry 機制處理（見 [09-A 結算狀態與失敗重試](affine://09-A)） |
| 領獎成功 | `code = 0` ＋ `voucher.settle_status = 2` ＋ `payout > 0` |
| 領獎但無派彩金額 | `code = 0` ＋ `payout = 0` → **仍須跳結算彈窗顯示 0**，不可靜默結束（見 03-T 驗收 ⑤） |

## 玩家端錯誤文案〔V1.19 新增〕

原則：**每一句都要告訴玩家「接下來可以做什麼」**（重新整理、回背包換遊戲、等倒數、稍後再試、聯繫客服），不能只說「失敗了」；**不出現技術詞**（ref、cache、AWC、settle 等）；**繁中每句 30 字以內**（含標點），寧短勿長。左欄是遊戲端回傳的訊息，前端依此對應顯示右側文案。

| 遊戲端訊息／狀態 | 玩家端文案（繁體中文） | English |
|---|---|---|
| `free voucher not found` | 找不到此卡，可能已過期，請重新整理背包 | Card not found — it may have expired. Please refresh your Backpack. |
| `game not supported by this voucher` | 此卡不適用本遊戲，請回背包改選其他遊戲 | Not valid for this game. Pick another game in your Backpack. |
| `invalid spin parameter for voucher` | 無法開始，請重新進入遊戲或聯繫客服 | Couldn't start. Re-enter the game or contact support. |
| `voucher rounds used up` | 次數已用完，獎金將自動入帳，請至背包查看 | No spins left. Winnings will be credited — check your Backpack. |
| `free voucher expired` | 此卡已過期，獎金將自動入帳，請至背包查看 | Card expired. Winnings will be credited — check your Backpack. |
| （空 message · Before StartTime） | 此卡尚未開始，請等倒數結束後再使用 | Not active yet. Please try again after the countdown. |
| `AWC free spin available for this game, please use it first` | 請先完成此遊戲的免費旋轉（DEV V1.7 定案，沿用 09-I `bag_fs_conflict_hint`） | Please finish the Free Spins in this game first |
| `free voucher not owned by member` | 此卡無法使用，請重新登入或聯繫客服 | Can't use this card. Log in again or contact support. |
| `free voucher settle failed` | 領取失敗，系統會自動重試入帳，無需重複領取 | Claim failed. We'll retry automatically — no need to claim again. |
| 領獎失敗但已 PENDING（settle_status = 4） | 獎金入帳中，請稍後查看錢包，無需重複領取 | Processing. Check your wallet shortly — no need to claim again. |

> ℹ️ 「領獎但無派彩金額」（`code = 0` ＋ `payout = 0`）**不另外顯示訊息**——照常跳結算彈窗顯示 0 即可（見 [03-T 驗收 ⑤](affine://03-T)）。
