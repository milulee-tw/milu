# 📋 00-B · 總流程與結算三步驟

> 依據：規格 DEV V1.16（源自 DEV V1.15）／ 後台原型 2026-08-25 實拍 ／ 背包原型 2026-09-14 新版線框
> 職能：📋 企劃&PM · ⚙ 後端

## 一、一句話

卡片一生走 8 步（抽中→發卡→背包→進遊戲→用完→結算），結算只做一次、只走三步。

## 二、規則一覽

| 規則 | 說明 |
|---|---|
| 8 步總流程 | 抽中 → 產卡序號 → 通知集成商建卡 → 入背包 → 背包點擊進入 → 遊戲中使用 → 結算觸發 → 整卡結算 |
| 結算三步 | 彙總暫存分數 score → 套用上限 final＝min(score, max_conversion) → 以「下注 0／派彩 final」注單入主錢包 |
| 三個觸發點 | 局數用完 ／ 卡片到期 ／ 玩家提前結算（僅封頂後可用）——先到者觸發 |

## 三、條列規則

- 整張卡只結算一次；三個觸發點以先到者為準。
- 遊戲過程中 Balance 完全不動，贏分只累加在暫存分數 score。
- final ＝ min(score, max_conversion)；超出上限的部分捨棄。
- 結算注單帶 campaign_id 與卡序號，放「一般注單」，Balance 於此刻增加。
- 卡內每一局的押注／贏分歷程不進一般注單，歸在「活動 › FREE SPIN 卡」分類（見 04）。
- 不另開金流：沿用遊戲本來就在跑的注單流，沒有紅利錢包、流水倍數或 roll-over。

## 四、詳細說明（DEV V1.15 原文，一字未改）

### 總流程（8 步 · 直式）

01. **抽中 FS 卡** — 抽寶箱判定中獎獎勵為非現金 FREE_SPIN

02. **產生卡序號** — 我方產生 reference_id，寫入快照

03. **通知集成商建卡** — 告知這張卡的幣別／效期／遊戲／次數，並取得成功確認

04. **入背包** — 狀態 ISSUED，玩家可見（卡名固定「{n}★ FREE SPIN」）

05. **背包點擊進入** — 綁定這張卡，取得一次性遊戲入口

06. **遊戲中使用** — 剩餘次數遞減；**每局贏分累加到暫存分數 score（不入 Balance）**；可切換列表內的其他遊戲；每局歷程留在「活動 › FREE SPIN 卡」分類

07. **結算觸發** — **局數用完（最後一次 FREE SPIN 結束）／卡片到期（到達 valid_to）／玩家提前結算（僅封頂後可用）——先到者觸發，整張卡只結算一次**

08. **整卡結算** — 給付 min(score, max_conversion)；以一筆注單入主錢包真金；剩餘未轉次數放棄

### 結算三步驟（暫存分數 score → 一律主錢包真金）

SETTLE 0 · 觸發. **局數用完 ／ 卡片到期 ／ 玩家提前結算（僅封頂後可用）——先到者** — 整張卡只結算一次；三個觸發點以先到者為準（提前結算規則見 DEV §07）

SETTLE 1. **彙總暫存分數 score** — 整張卡每一局的贏分都只累加在 score，過程中 Balance 完全不動

SETTLE 2. **套用上限 max_conversion** — final ＝ min(score, max_conversion)：score 超過上限給上限、未超過給 score；超出部分捨棄

SETTLE 3 · 入主錢包真金. **以「下注 0 / 派彩 final」注單發放** — 產生一筆零下注中獎注單（帶 campaign_id 與卡序號）——**這筆注單放「一般注單」**，Balance 於此刻增加，並以 bet=0 發放方式與平台／集成商同步資產增加。無流水、無 roll-over。

> **FREE SPIN 押注歷程單獨分類**：卡片內每一局 FREE SPIN 的押注／贏分歷程**不放一般注單**，歸在「**活動 › FREE SPIN 卡**」分類留存（對帳與客訴查詢用）；**只有最後那筆結算注單進一般注單**。 V1.12 補 **玩家怎麼查得到這些局**：入口與四層畫面規則見 DEV §09。

> **為什麼是注單而不是另開一條金流**：獎勵即真金，搭遊戲本來就在跑的注單流送出，*不需要第二條金流管線*，也不需要紅利錢包、流水倍數或 roll-over。封頂由我方結算層自己算好再送出。
