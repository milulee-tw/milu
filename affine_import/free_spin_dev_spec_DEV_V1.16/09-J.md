# ⚙ 09-J · 事件紀錄

> 依據：規格 DEV V1.16（源自 DEV V1.15）／ 後台原型 2026-08-25 實拍 ／ 背包原型 2026-09-14 新版線框

## 一、一句話

要記什麼、為了回答什麼問題——客訴與對帳導向；回報問題時直接講事件名即可。

| 事件名 | 為了回答什麼問題 |
|---|---|
| fs_card_issued | 客訴「我沒收到卡」 |
| fs_awc_create | 「卡發了但背包沒出現」 |
| fs_activate | 「扣錯卡／啟用錯卡」多卡歧義爭議 |
| fs_round_used | 「次數被多扣／少扣、分數不對」 |

## 三、條列規則

- 本頁不定義欄位格式，只定義「要記什麼、為了回答什麼問題」。
- 另有四個輔助事件：fs_bag_view（曝光）、fs_launch（取入口結果）、fs_settle_shown（結算彈窗曝光與關閉）、fs_history_open（開啟歷程）。
- 完整事件清單與說明見下方原文。

## 四、詳細說明（DEV V1.15 原文，一字未改）

> **寫給誰看**：這一章不定義欄位格式，只講「**要記什麼、為了回答什麼問題**」——客訴與對帳導向。事件名為系統識別碼，回報問題時直接講事件名即可。

- 事件記什麼 · 為了回答什麼問題

- fs_card_issued發卡紀錄：這張卡（reference_id）何時發、來自哪檔活動（campaign_id）、哪款卡（reward_id）、幣別與面額——客訴「**我沒收到卡**」查這裡。

- fs_awc_create通知集成商建卡的請求與結果（成功／失敗／序號已存在）——「**卡發了但背包沒出現**」的排查起點。

- fs_bag_view玩家開背包查看 FREE SPIN 卡——曝光行為，輔助排查「**看得到但用不了**」類回報。

- fs_activate進場前綁定啟用：綁了哪張卡（reference_id）＋哪款遊戲（game_id）——「**扣錯卡／啟用錯卡**」的多卡歧義爭議查這裡。

- fs_launch取一次性遊戲入口的結果（成功／失效重取）——「**點了進不去遊戲**」排查。

- fs_round_used每局扣次與贏分：rounds_left 變化、該局贏分與累加後的 score、發生在哪款遊戲（歸「活動 › FREE SPIN 卡」分類）——「**次數被多扣／少扣、分數不對**」爭議查這裡。

- fs_settle_shown結算彈窗曝光與關閉：何時顯示給玩家、由哪個出口關閉（Return／✕）、是否為斷線後補顯示——客訴「**沒看到結算畫面／不知道結束了**」查這裡。

- fs_early_settle**玩家主動提前結算**：哪張卡（reference_id）、**放棄的局數**、**入帳金額**（＝max_conversion）、確認時間——客訴「**我的次數怎麼不見了**」查這裡（DEV V1.6 新增）。

- fs_settled整卡結算：score、實付金額 min(score, max_conversion)、campaign_id 與卡序號、對應的一般注單——客訴「**少給錢**」查這裡。

- fs_history_open**玩家開啟 FS 歷程**：來源（CRM 選單 History／遊戲歷程分類）、開啟當下的持卡數與已結算卡數、展開了哪張卡（reference_id）——用來回答「**玩家到底查不查得到、查不查得懂**」，以及客訴前是否曾自助查詢過（DEV V1.12 新增）。

- fs_expired逾期紀錄：剩餘未轉局數、是否已觸發結算——「**卡怎麼不見了**」爭議查這裡。
