## 三、條列規則

- 次數用完的結算由最後一局結束時即時觸發，不靠排程；排程只負責掃「已到期」的卡。
- ④ 的查詢時機是兩道防線：背包展開卡片載入遊戲牆時查一次、進場啟用前再驗一次。查詢介面尚未就位時，這個檢查不得默默略過。
- ⑤ 一般注單與 FS 歷程必須吃同一份來源，兩處各自維護必然出現「背包 score 與歷程局數加總對不起來」的對帳爭議。
- ⑤ 同時連動 RTP 判斷、對帳與活動數據統計，不宜與 CRM 功能開發搶同一批後端人力。

## 四、詳細說明（DEV V1.15 原文，一字未改）

> **基礎建設 · 先做，否則全卡關**：以下五項是地基，任何一項沒先就位，發卡、結算或查詢的鏈路就動不了。

> 🔐 ① 與集成商往來憑證的安全保管 基建 與集成商往來所需的憑證／金鑰，須存放在安全位置並由專責模組使用，不得散落在程式碼或設定檔明文中。 **沒先做會卡什麼：**無法與集成商建立可信往來，發卡通知完全送不出去。

> ⏰ ② 每日結算與過期掃描排程 基建 伺服器定時掃描「已到期」的卡並觸發整卡結算與狀態轉換（**次數用完的結算由最後一局結束時即時觸發**，不靠排程）。 **沒先做會卡什麼：**到期卡不會被結算、玩家拿不到錢；過期卡也不會轉唯讀，客訴必然發生。

> 🎫 ③ 一次性遊戲通行證＋防連點 基建 進入遊戲的一次性入口產生、失效重取、與同卡節流機制。 **沒先做會卡什麼：**玩家點「進入遊戲」會遇到連結失效死路，多卡綁定也無從保證。

> 🔎 ④ AWC FREE SPIN 狀態查詢 基建 V1.6 新增 需**集成商提供「玩家 × 遊戲」維度的 AWC FS 進行中狀態查詢介面**。**查詢時機＝背包展開卡片載入遊戲牆時 ＋ 進場啟用前再驗一次**（兩道防線）。 **沒先做會卡什麼：**同一款遊戲同時存在 AWC FS 與 COMBO FS 卡時兩者互相干擾，玩家會遇到「卡使用失敗」卻查不出原因，次數與 score 也可能對不起來。

> 🗂️ ⑤ FS 歷程獨立 DB ＋ 歷程 API 統一輸出 基建 V1.12 新增 FS 卡的每一局**不進一般注單**，需**獨立設計 DB 架構與邏輯**；同時**遊戲歷程 API 須調整為「同一份資料輸出」**——一般注單與 FS 歷程**吃同一份來源**，不得兩處各自維護。 **沒先做會卡什麼：**DEV §09 的四層畫面**全部沒有資料可撈**，玩家與客服都查不到 FS 的任何一局；兩處各自維護則必然出現「背包顯示的 score 與歷程列出的局加總對不起來」的對帳爭議。 **連動範圍：**此項同時連動 RTP 判斷、對帳與活動數據統計，**不宜與 CRM 功能開發搶同一批後端人力**。
