### 待確認事項 ⑤–⑦（承接 §12 的編號） （更新 2026-09-01）

> **編號為什麼從 ⑤ 開始**：本文件的待確認事項**共用一套流水號**。①–④ 與 ⑧–⑪ 屬「與集成商／後端／前端確認」放在 §12；**⑤–⑦ 屬「與遊戲端確認」且緊扣本章的全域規則，故留在此處**。引用時請連章號一起寫（如「§03 待確認⑤」），避免查錯地方。

- 【與遊戲端確認】⑤ FS 模式下 **AUTO 自動旋轉是否開放**？若開放，自動局數須以剩餘局數為上限、用完即停。

- 【與遊戲端確認】⑥ **卡片局數與遊戲自身免費遊戲局數並存時的畫面表現**（兩個計數器並列？暫時隱藏其一？）。規則面已定：遊戲自身免費局不扣卡片局數、贏分照樣累加。

- 【與遊戲端 / 客服確認】⑦ 結算彈窗是否**同時顯示卡序號 reference_id**（客服查單以卡序號最快），或維持只顯示 CampaignID。

### 待確認事項（未決 · 影響實作行為）

- 【與集成商確認】① 發卡時能否由我方指定「每轉押注」？若不能，押注大小如何決定？

- 【與集成商確認】② 集成商能否支援「指定啟用某一張卡」（帶卡序號）？若不支援，退回備援方案：玩家自背包點擊執行該卡。

- 【與集成商確認】③ 一次性遊戲入口的取用頻率限制與失效重取建議（同玩家短時間多卡／連點時的行為）。

- 【與集成商確認】④ 結算資料回灌的方式與時間差（約 5–10 分鐘）對「整卡結束才給獎」時序的影響。

> **⑤–⑦ 不在本章**：待確認事項共用一套流水號，**⑤⑥⑦ 屬「與遊戲端確認」且緊扣全域規則，放在 §03 章末**（⑤ AUTO 是否開放／⑥ 卡片局數與遊戲自身免費局並存的畫面表現／⑦ 結算彈窗是否顯示卡序號）。本章為 ①–④ 與 ⑧–⑪。

- 【與遊戲端確認】⑧ **盤面資料的保存期限**：一般注單的盤面回放保存多久？FS 局歷程是否採**同一保存政策**？逾期後仍須保留「時間／Bet／Win／reference_id」四項數字（§09 Ⓕ），此點需寫入 DB 設計。

- 【與遊戲端確認】⑨ **局歷程列能否回傳遊戲名**：§09 Ⓓ 的 Time 欄第二行需顯示該局所屬遊戲；若歷程 API 不含 game_id / game_name，需確認補欄位的成本，或退回備援方案（該卡若跨多款遊戲則在展開區頂端列出遊戲清單、不逐列標示）。

- 【與遊戲端確認】⑩ **結算收尾列能否跨分類跳轉**：§09 Ⓔ 希望點結算列可跳到一般注單的那一筆。若歷程頁不支援跨分類跳轉，**降級為不可點但顯示注單 ID＋複製 icon**（規格已寫入降級行為，此題只影響體驗不影響上線）。

- 【與前端確認】⑪ **盤面元件重用成本**：內部 wiki《玩家遊戲歷程與獎勵記錄架構》原記載「歷程以數字呈現、**不重現遊戲盤面**」，該原則的成本理由建立在「盤面要另外做」之上。現況一般注單的盤面回放**已上線**，本章採**重用既有元件、只置換頂部三個數字**的做法，故 wiki 該段已標記 OUTDATED。需前端確認重用成本確實如評估般低；若不然，退回備援方案（L4 列不可點、不做 L5）。
