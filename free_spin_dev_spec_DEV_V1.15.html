列表鎖定可玩遊戲列表在發卡當下決定，遊戲中不可新增 / 移除

剩餘次數結算時未轉的剩餘次數視同放棄，不補轉、不折現；已累積的贏分照常結算給付

區域詳細說明 · 畫面二

ⒶFREE SPINS 模式常駐標記整場都掛著，代表「現在是免費局」。

限制與規則
  • 從第一局開始顯示，到結算彈窗關閉後移除
  • v1 純標示、點擊不做事；「點開看卡片摘要」列 v2 候選
防呆與錯誤
  • 回一般模式後必須消失，否則玩家會以為還在免費局

Ⓑ剩餘局數計數器（取代 SPIN 鈕）原本的旋轉鈕位置改成「FREE {n}」。

限制與規則
  • n＝剩餘局數，每完成一局 −1；n 歸 0 後不可再開新局，直接進結算
  • 遊戲本身觸發的免費遊戲期間 n 停住不動（那些局不扣卡片局數）
  • 「FREE」字樣為美術圖、數字為動態值
防呆與錯誤
  • 扣次以我方紀錄為準；畫面與紀錄不一致時不得多扣
  • n＝0 時按鈕不可再按（避免玩家再按一下變成真錢局）

限制與規則
  • 顯示本局贏分，不顯示整張卡的累積 score（本版定案：遊戲中不揭露累積與封頂進度）
  • 累積金額與封頂進度只在背包 Ⓓ 進度條與結算彈窗看得到
防呆與錯誤
  • 贏分只累加到 score，不得同步加到錢包餘額

防呆與錯誤
  • 玩家嘗試改押注時無反應即可，不需跳錯誤訊息
  • 押注欄須有明確的鎖定標示：顯示小標籤「已鎖定 · 免費旋轉」（LOCKED · FS）並配合虛線外框——只把加減鈕灰化，玩家會以為是當機V1.14 補

為什麼取消「遊戲」這一層（設計取捨，開發請勿自行加回）
一張 FS 卡最多可指定 8 款遊戲，玩家可能同一張卡在 A、B 兩款都玩過。若先分遊戲再分卡，同一張卡的歷程會被切成兩截，而「累積分數 score」與「封頂 max_conversion」都是整張卡計算的——切開後任何一邊都算不出正確數字，只會製造客訴。
卡才是 FS 的結算單位，遊戲不是。玩家的問題永遠是「我這張卡拿了多少」，不是「我在這款遊戲用卡拿了多少」。遊戲維度改以 L4 列上的遊戲名標示保留。

L2 · 活動分類頁

ⒶFREE SPIN 卡入口卡與抽寶箱並列的第二張入口卡。

限制與規則
  • 卡片＝icon ＋名稱「FREE SPIN 卡」，尺寸同抽寶箱卡
  • 卡片下方不顯示任何統計數字（無 TOTAL BETS／Net Win/Lose）——它是純入口，不是投注統計分類
  • 兩張入口卡點進去的結構不同：抽寶箱＝單層獎勵列表且列不可點、無次層頁面（DEV V1.13 補記：抽寶箱玩家端不顯示 CAMPAIGN ID、不分組，列上第二欄為注單 ID，見抽寶箱 DEV V1.22）；FREE SPIN 卡＝三層可鑽（L3→L4→L5），卡片列可展開、局列可進盤面。前端不要當成同一個元件共用
    相同處：兩者上方都有日期選擇器（同一元件），但作用對象不同——抽寶箱篩「獎勵列」（單層、每列即一筆獨立獎勵）；FS 卡篩「有使用紀錄的卡片」且不裁切展開後的局數（score 需與列出的局對得起來）。此差異為刻意設計、不得統一（見下方 L3 Ⓒ 日期篩選器）。
  • 未來其他 CRM 玩法（簽到、任務…）以同樣卡片並列，版面預留
防呆與錯誤
  • 玩家從未取得過 FS 卡：入口卡照常顯示，點進 L3 顯示空狀態文案
  • 入口卡不因卡片全數過期而隱藏（歷史查詢需求不隨卡片消失）
L3 · FREE SPIN 卡片清單

Ⓑ卡片列（分組標頭）一張卡一列，reference_id 為主鍵；點列展開該卡全部局。

限制與規則
  • 排序＝發卡時間倒序（最新的卡在最上面）
  • 每列欄位（自左至右）：
    ① 卡名「{n}★ FREE SPIN」（同背包固定卡名）
    ② reference_id 短碼＋複製 icon（樣式仿既有 ID 欄；點複製取完整值）
    ③ 有效期間 valid_from ~ valid_to
    ④ 已用／總次數（如 8/10）
    ⑤ 累積分數 score——純數字、不帶幣值符號
    ⑥ 結算金額——帶幣值符號、橘黃色；未結算顯示「進行中」灰字
    ⑦ 狀態徽章（使用中／已結算／已過期未使用）
    ⑧ 展開 chevron
  • ⑤與⑥的視覺必須有差別：⑤是分數（無幣值）、⑥是真金（有幣值）。這是本頁最容易被玩家誤解的一組數字
  • score 已達封頂：⑤ 仍顯示實際 score，其後加小字「已封頂，結算以上限為準」
  • 展開為手風琴：一次只展開一張卡（避免長列表迷路）
防呆與錯誤
  • 卡片已發但玩家從未開打：可展開，L4 顯示「此卡未使用過」，結算欄顯示「未使用」
  • 卡片仍在使用中：結算欄一律「進行中」，不得顯示預估金額（避免玩家把預估當承諾）
  • 已過期未使用的卡仍列出並置灰，供客訴查詢
  • 清單為空（玩家從未取得 FS 卡）：置中顯示空狀態文案，不顯示表頭

Ⓒ日期篩選器篩出「該日期有使用紀錄」的卡片。

限制與規則
  • 作用對象＝卡片清單：選定日期後，只列出該日期當天有至少一局使用紀錄的卡
  • 不是用來篩「該日期發的卡」，也不裁切展開後的局數——展開仍顯示該卡全部局（否則 score 與列出的局對不起來）
  • 預設值＝不篩選（全部）；玩家主動選日期才生效，並顯示「清除篩選」
  • 樣式沿用既有遊戲明細頁的日期選擇器元件
防呆與錯誤
  • 選到沒有任何使用紀錄的日期：顯示「該日期無使用紀錄」＋「清除篩選」按鈕，不要顯示空白畫面
  • 日期以 UTC+8 判定（同全站時區慣例，見 §03）
L4 · 該卡的局歷程（展開區）

Ⓓ局歷程列表沿用既有注單列表元件，維持四欄。

限制與規則
  • 不顯示單日統計列（無 Single Day Bet Amount／Single Day Net Win Loss）——FS 局不扣真金、贏分不入 Balance，顯示這兩個數字會讓玩家誤以為自己輸了錢
  • 欄位維持既有四欄（reference_id 已上移至分組標頭，不必再佔一欄）：
    Time｜ID｜Profit｜Special
  • Time 欄改雙行：上行＝時間 MM/DD HH:MM:SS；下行＝遊戲名（小一號灰字）。若該卡只用過一款遊戲，下行不顯示
  • Profit 欄＝該局贏分，純數字不帶幣值符號；中獎為橘黃、未中獎顯示 0 灰字。不顯示負數、不顯示 bet（FS 局沒有扣款這件事）
  • Special 欄沿用既有（Free Game 觸發等標記）
  • 列右側保留 chevron，點擊 → L5 盤面
  • 排序＝時間倒序，跨遊戲混排
  • 頁首固定說明列（不可關閉）：「此頁數字為卡片面額與累積分數，非帳戶餘額；實際入帳金額請見結算列。」
防呆與錯誤
  • 遊戲已下架：遊戲名照常顯示（取快照留存值），點進 L5 若盤面資產已移除則顯示降級提示，數字部分仍須正確
  • 單張卡局數上限有限（依卡片次數），不需分頁；若日後開放大次數卡再議
  • 卡片未使用過：顯示「此卡未使用過」，仍顯示結算列（結算金額 0 或未結算）

Ⓔ結算收尾列把「分數」接回「真金」的那一列。

限制與規則
  • 固定置於該卡展開區的最下方（時間倒序之外的獨立列，樣式與局列有明顯區隔：底色略亮＋上緣分隔線）
  • 內容：時間＝結算時間｜標籤「結算 · 已入主錢包」｜金額＝min(score, max_conversion)，帶幣值符號、橘黃色
  • 可點 → 跳至一般注單中對應的那一筆「下注 0／派彩 final」注單（跨分類跳轉，見 §12 待確認⑩）
  • 卡片尚未結算：不顯示本列（不要顯示 0 或預估值）
  • 提前結算（§07 Ⓓ′）與到期／局數用完結算走同一列，不另做樣式
防呆與錯誤
  • score 超過封頂：本列金額顯示實付的上限值，並在其下以小字註明「累積 {score}，上限 {max_conversion}，超出不計」——這是「少給錢」客訴的第一現場
  • 跨分類跳轉若遊戲端不支援：降級為不可點，並在列上顯示注單 ID 短碼＋複製 icon，讓客服可自行查
L5 · 單局獲獎盤面

Ⓕ盤面頁欄位置換沿用既有元件，只動頂部三個數字。

限制與規則
  • 盤面本體（轉軸、符號、倍率、Free Game 標記）完全沿用既有遊戲歷程元件，不做任何客製
  • Balance 區塊整組置換：既有的「前值 ／ ▼ ／ 後值」三行 → 改為單行 reference_id（標籤「卡序號 / Reference ID」，完整值＋複製 icon）。不顯示任何 Balance 前後差異——FS 局本來就不動 Balance，顯示了必然對不上
  • Bet＝該卡的每轉押注面額（來自發卡快照 bet），帶幣值符號，其下加小字「卡片面額 · 未實際扣款」
  • Win＝該局贏分，純數字不帶幣值符號（與 L4 Profit 欄同口徑）
  • 頂部日期時間列（YYYY/MM/DD HH:MM (GMT +08:00)）沿用既有
  • 「Normal Spin／Free Spin」等既有標記沿用
防呆與錯誤
  • Bet 帶幣值、Win 不帶幣值是刻意的不對稱：面額是卡片定義的固定值（可對照背包），贏分在結算前不是錢。開發請勿「順手統一」
  • 盤面資料已逾保存期限：顯示「此局盤面已逾保存期限」，但時間／Bet／Win／reference_id 四項仍須顯示（保存期限見 §12 待確認⑧）
  • ← 返回回到展開狀態的 L4，不得回到收合的 L3（避免玩家每看一局就要重新展開）
